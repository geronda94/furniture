# 41 — Карта кода и контракт поведения

Дата: 2026-11-02. Зафиксировано перед добавлением ИИ-функций: что где лежит,
что считается рабочим контрактом и что нельзя ломать.

## 1. Слои и поток данных

```
specs/                 данные цеха, фурнитуры, материалов, цен
tools/furniture_core/  детерминированный движок: деталировка, раскрой, смета,
                       план, объёмные коллизии, стандарты
apps/api/              HTTP, auth, хранение, solve/validate/actions
apps/web/src/          Vue 3 + Babylon: состояние, рендер, UI
docs/                  правила, решения, эта карта
```

Поток: `params` → API `solve` → `derived[]` → 3D/2D + смета.
UI **не считает** деталировку сам; движок **не знает** про HTTP/Vue.

## 3. Контракт поведения (не ломать)

### Выделение
- Обычный клик — **строго один** активный элемент: модуль **или** деталь.
- Группа — только Shift/Ctrl/Alt.
- Клик по пустому месту снимает и модуль, и деталь.
- Выделение показывает пунктирный контур по силуэту, без оранжевой заливки
  рёбер.

### Камера
- Если объект уже вписан (≥ ~32% кадра, в центре, цель внутри габарита),
  клик по нему/деталям **не двигает камеру**.
- Иначе — плавный доворот за ~0,45 с; ввод пользователя отменяет анимацию.

### Размеры
- «Внутри» — детали; «Снаружи» — до стен/соседей; «Зазоры» — все полки/ящики.
- Цвета: Ш жёлтый, В зелёный, Г синий, абсолют светло-оранжевый,
  относительный фиолетовый; стена светло-серая, сосед серый.
- Ширина отдельной подсветкой грани не дублируется.
- Абсолютные ↓/↑ — короткий отрезок у левого угла дна/крыши под стрелкой.
- Относительные — правая треть ребра, у вертикальной линии размера; у
  просвета подсвечиваются обе полки.
- Внешние размеры считаются лучом до **ближайшей стены/перегородки**, поэтому
  объект из другой комнаты не перебивает стену; показываются все стороны
  с зазором > 0.
- Кнопки размеров — в глобальной панели над канвасом; на телефоне — в шторке
  «Вид».

### Перемещение и размер
- X/Y/Z, Ш/В из карточки не пускают в стену/проём/потолок/соседа; при упоре
  значение подрезается, поле возвращает фактическое.
- Навесной шкаф не ниже 1100 мм.
- Пролёт полки > 1100 мм блокируется с сообщением «добавьте стойку».
- Ширина/высота пересчитывают деталировку и 3D.

### Стены
- «◩ Срез» — стены перед камерой скрываются; «▦ Все стены» — все стены.
- Никакого опускания стен.

### Пол и ручки
- Пол — поверхность на `z=0`, с UV и правильным обходом; мебель на 0,
  цоколь 0…100 мм.
- Ручки — сборки из цилиндров, дочерние к створке, двигаются с ней.

### Валидация
- Список проблем с галочками и «Исправить выбранные»; фиксы физически меняют
  параметры/позицию.
- «Щель у стены» сдвигает ряд к стене.
- Геометрические нарушения блокируются на фронтенде сразу.

### Полное управление через чат
- `apps/api/actions.py` — все типизированные `op` для ИИ и UI;
  `room.py` — комната/стены/проёмы, `fixes.py` — физические фиксы,
  `placement.py` — свободные места. Каталог инструментов и правила —
  `apps/api/ai_tools.py`, матрица возможностей — `docs/43`.
- Клиентская сторона: `ai/context.ts` (снимок), `ai/tools.ts` (вид, проекты,
  чтение, файлы), `AiChatPanel.vue` (накопление пакета → preview → apply).
- Инструменты с `confirm=true` — только удаление данных; за пакет ≤ 12
  операций; новые проекты открываются с переносом диалога.

### Автопостановка и действия ИИ (API)
- `apps/api/plans.py` + `routers/plans.py` — импорт планов (PDF/изображение/
  DXF/SVG), vision-разбор, `POST /api/projects/{id}/plan`; клиент —
  `ai/tools.ts`/`AiChatPanel.vue` (карточка плана). Контракт — `docs/44`.
- Пустой проект не должен получать демо-мебель: `normalizeProject` берёт
  `instances` только если это массив (в т.ч. пустой).
- `apps/api/placement.py` — единственное место, где ищется свободное место;
  геометрия берётся из `furniture_core.scene`, правила — как у валидатора.
- `scene_context` считается один раз на перебор позиций; дальше сравнение по
  габаритам. `candidate_free` учитывает стены, проёмы, двери/ящики соседей,
  створки соседей, декор, настенные предметы, потолок и окна под навесными.
- `add_instance` / `add_decor` / `add_wall_item` без координат ставят сами;
  с координатами — проверка и отказ с подсказкой свободного места.
- `update_instance` проверяет перенос, поворот и габариты (материалы и
  название — без проверки).
- Координаты — обе или ни одной; модуль выше потолка — отказ с причиной.
- Пресеты каталога (API и web) должны проходить валидатор без ошибок.

## 4. Тесты (контракт)

- Python: `tests/golden.py`, `geometry.py`, `features.py`, `layout.py`,
  `scene.py`, `standards.py`, `cutting.py`.
- e2e: `smoke`, `workbench`, `ui-audit`, `camera`, `touch`, `selection`,
  `camera-focus`, `size-row`, `pos-limits`, `outer-dims`, `validation`,
  `ai-context`, `ai-chat`, `ai-chat-flow`, `ai-placement`,
  `ai-design-flow`, `ai-part-material`, `ai-plan-import`.
- Перед деплоем: `tsc`, `npm run build`, `tools/deploy.sh`, затем e2e на проде.
- e2e запускать с `PW_CHROME=/usr/bin/google-chrome` (браузеры Playwright на
  сервере — другой версии) и `BASE_URL=http://127.0.0.1:5176`. Для `smoke`
  `BASE_URL` обязателен, иначе он смотрит на локальный `4173`.

## 5. Куда добавлять ИИ

1. **Действия над проектом** — `apps/api/actions.py` (атомарные операции,
   валидация до сохранения) + `state/project.ts` для применения результата.
2. **Генерация параметров** — `tools/furniture_core` (чистый движок) и
   `api`-роут, не в компонентах.
3. **Подсказки/чат** — отдельный слой, который читает `state`/`derived` и
   вызывает actions; не дублировать формулы в UI.
4. **Проверки ИИ-результата** — strict-PUT / `validate` (docs/22), плюс
   клиентские проверки из `state/project.ts`.

## 6. Оставшийся технический долг

- `state/project.ts` (~125 КБ) и `render3d/babylonScene.ts` (~130 КБ) всё ещё
  крупные: следующие безопасные шаги — вынести `setInstancePosition`/
  `resizeModule`/`canPlace*` в `state/placement.ts`, а `syncProps` — в
  `render3d/props.ts`.
- Часть нормативных фиксов валидации ручная (помечено в UI).
- Мебель сцены (диваны/комоды) не в BOM — это объекты сцены.
