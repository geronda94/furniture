# 32 — Инструкция: что исправить до перехода на ИИ-управление

Дата: 2026-10-29. Статус: рабочий план. Цель — довести проект до состояния,
когда ИИ может вести проектировку через инструменты, а человек — проверять и
править, без «тупняков» и сломанных проектов.

## 0. Где мы сейчас

По коду и `docs/26` большая часть аудита P0–P2 уже закрыта:

- strict-сохранение и preflight в UI;
- `normalize_scene` ~0.56 с вместо 7 с;
- `H_total`, задняя стенка, зум развёрток, словарь ошибок;
- ленивый solver, sequence для проверки расстановки;
- rate limit, cookie/secret, бандл Babylon отдельным чанком;
- тесты `golden/geometry/features/layout/scene/standards` зелёные.

Осталось три вещи, и они не равны:

1. **Юзабилити и производительность 3D** — субъективно «хромает», реальных
   замеров на целевом железе нет.
2. **AI-контракт** — сейчас `ActionIn.actions: list[dict]`, 6 операций,
   текстовый `/api/ai/guide`. Это низкоуровневый API, а не инструменты для ИИ.
3. **Чат** — его нет вообще: ни панели, ни эндпоинта, ни сессии, ни eval.

Вывод: ядро готово, оболочка для ИИ — нет. Переходить на ИИ сейчас нельзя:
он получит сырой JSON и будет ломать проект.

## 1. Definition of Ready — когда можно включать ИИ

Переход разрешён, когда выполнены все пункты:

- 0 сохранённых проектов с ошибками за 2 недели (strict + preflight + тест).
- `normalize` < 300 мс на демо-квартире; UI не блокируется.
- 3D: ≥ 30 FPS на целевом ноутбуке, ≥ 24 FPS на среднем телефоне,
  загрузка сцены < 2 с; есть замер и HUD.
- У каждой ошибки есть человеческий текст, объект и действие «Показать»;
  где безопасно — «Исправить».
- 12 типизированных операций покрывают 90% сценариев; у каждой есть
  JSON Schema, пример, предусловия и ошибки.
- `preview/diff` работает для всех операций: было → стало, ошибки,
  стоимость, без сохранения.
- 20 eval-сценариев: ≥ 80% успеха, 0 испорченных проектов, среднее число
  правок ≤ 2.
- Чат: apply/undo, снимок версии перед пакетом, подсветка изменений.
- 5 мастерских посмотрели; 3 сказали «понятно и удобно».

## 2. Гейт 0 — стабильность (без этого ИИ запрещён)

### S1. Атомарность пакета операций

Сейчас `apply_action` мутирует `doc` по одной операции. При ошибке в середине
пакета `commit=false` может вернуть частично изменённый документ.

Сделать: работать с копией, применять пакет целиком, при ошибке возвращать
исходный документ и список ошибок по операциям.

Приёмка: пакет из 3 операций, вторая падает → документ не изменился, ответ
содержит `failed_index`, `results`.

Файлы: `apps/api/actions.py`, `apps/api/routers/projects.py`,
`tests/api.py`.

### S2. Одна запись истории на пакет

ИИ и нормализация должны откатываться одним «Отменить», а не 20 шагами.

Сделать: `pushHistory('ИИ: пакет')` перед применением; для API — снимок
версии до `commit=true` (опционально `snapshot=true`).

Приёмка: после пакета из 5 операций одно нажатие Undo возвращает всё.

### S3. Идемпотентность

Повтор одного и того же запроса не должен добавлять второй шкаф.

Сделать: `request_id` в `ActionIn`; хранить последние N применённых id
на проект; повтор возвращает прежний результат.

Приёмка: два одинаковых POST с одним `request_id` → один модуль.

### S4. Регрессия «невалидное не сохраняется»

Preflight уже есть. Добавить E2E: подвинуть шкаф в стену, нажать сохранить →
тост, `PUT` не ушёл, проект на сервере прежний.

Файлы: `tests/e2e/smoke.mjs` или новый `tests/e2e/strict-save.mjs`.

### S5. Аудит действий ИИ

Логировать: кто, когда, какие операции, какие ошибки, что применено.
Без этого нельзя разбирать «ИИ сломал проект».

Приёмка: `GET /api/projects/{id}/actions/log` или запись в версии/историю.

## 3. Гейт 1 — юзабилити и 3D

### U1. Режимы «Мастер» и «Эксперт»

Главная проблема юзабилити — не отдельная кнопка, а когнитивная нагрузка:
после QuickStart пользователь попадает в «кабину самолёта» из панелей.

Сделать:

- **Мастер** (по умолчанию для новых): комната → проёмы → сценарий →
  результат; скрыть продвинутые панели; одна главная кнопка на экран.
- **Эксперт**: всё как сейчас.
- Переключатель в меню; запоминать выбор.

Приёмка: новый пользователь без подсказок собирает кухню за ≤ 10 минут;
5 тестовых пользователей, 4 без помощи.

Файлы: `App.vue`, `QuickStart.vue`, `TopBarMenu.vue`, `state/project.ts`.

### U2. «Следующий шаг» в статусбаре

Пользователь не должен думать, что делать дальше.

Правила: нет комнаты → «Задайте комнату»; нет модулей → «Добавьте модуль»;
есть ошибки → «Исправьте расстановку (N)»; всё ок → «Скачайте проект».
Клик ведёт к действию.

Файлы: `StatusBar.vue`, `state/project.ts`.

### U3. 3D: замер, потом оптимизация

Сейчас есть `?perf=1`, авто-качество, 2D-fallback, но реальных замеров на
телефоне нет. Сначала измеряем, потом трогаем.

Сделать:

- замер FPS/времени кадра на 3 сценах: 5 модулей, 15 модулей, 30 модулей;
- HUD с draw calls, meshes, materials, textures;
- цели: ноутбук ≥ 30 FPS, телефон ≥ 24 FPS, загрузка < 2 с;
- если не проходит: LOD, thin instances, merging по материалу, culling,
  отключение теней/SSAO на слабых, pixel ratio cap, render scale,
  заморозка материалов, отказ от пересборки всей сцены на каждое изменение.

Приёмка: отчёт с числами до/после на целевом устройстве.

Файлы: `render3d/babylonScene.ts`, `View3D.vue`, `tests/e2e/perf.mjs`.

### U4. Загрузка и отмена

Расчёт 5–10 модулей не должен выглядеть как зависание.

Сделать: скелетон/прогресс, «Отменить», не блокировать UI, показывать
«расчёт N из M», кэш уже посчитанного.

Приёмка: нет белого экрана > 300 мс; можно отменить.

### U5. Ошибки с действием

Сейчас коды переведены, но не все ведут к объекту и исправлению.

Сделать: `issue = {code, severity, object_id, message, fix, auto_fixable}`;
кнопки «Показать» (фокус в 3D/плане) и «Исправить» (если безопасно:
нормализация, прижатие к стене, разведение декора).

Приёмка: 90% ошибок имеют объект и действие; 0 «сырых» кодов.

### U6. Мобильный путь

Проверить на 390×844: вход, QuickStart, 3D, развёртки, объект, сохранение,
экспорт. Нет тупиков, нет горизонтального скролла, кнопки ≥ 44 px.

Файлы: `tests/e2e/touch.mjs`, `docs/31-device-checklist.md`.

### U7. Длинные стены и печать

Зум/панорама уже есть. Добавить: перенос подписей, «вписать», печать/PDF/SVG
развёртки, читаемость на 9000 мм.

### U8. Понятность результата

«Готовый проект» должен отвечать: что заказать, что резать, что сверлить,
что купить, сколько стоит, что проверить. Один экран + один пакет выгрузок.

Проверить: цех по выгрузке может собрать без звонков (пилот).

## 4. Гейт 2 — AI-контракт

### A1. 12 типизированных операций

Вместо `list[dict]` — Pydantic discriminated union и JSON Schema.

Минимальный набор:

1. `add_module`
2. `update_module`
3. `delete_module`
4. `move_module` (x/y/z/rot)
5. `add_opening`
6. `update_opening`
7. `delete_opening`
8. `add_wall_item` (розетка/выключатель/полка)
9. `update_wall_item`
10. `delete_wall_item`
11. `add_decor` / `update_decor` / `delete_decor`
12. `set_room` / `set_globals` / `set_project_materials` / `apply_template`

У каждой: вход, предусловия, эффект, ошибки, пример, `auto_fixable`.

Приёмка: `/api/ai/tools` отдаёт JSON Schema; LLM может вызвать операцию без
чтения исходников.

### A2. `preview/diff`

`POST /api/projects/{id}/preview`:

- применяет пакет в памяти;
- возвращает `before/after`, список изменённых объектов, ошибки, стоимость,
  warnings;
- ничего не сохраняет.

Приёмка: чат показывает «добавится 3 модуля, смета +€420, ошибок 0» до
применения.

### A3. Машинно-читаемая валидация

Каждая ошибка: `code`, `severity`, `object_id`, `message`, `fix`,
`auto_fixable`. Плюс `GET /api/ai/errors` со словарём кодов.

Приёмка: ИИ может по ошибке выбрать fix без угадывания.

### A4. Дизайн-сессия

`POST /api/design/session` → `{goal, room, constraints}`;
`POST /api/design/session/{id}/plan` → предложенные операции;
`POST /api/design/session/{id}/apply` → preview/commit;
`POST /api/design/session/{id}/undo`.

Сессия хранит шаги, версии, ошибки, решения человека. Это не чат, это
состояние проектирования.

### A5. Eval-набор

20 сценариев на естественном языке:

- «Кухня 3×4, окно справа, мойка у окна, холодильник в углу»;
- «Гардероб 2.5 м до потолка, три секции, штанга и полки»;
- «Убери пенал, добавь ящики»;
- «Подвинь шкаф, чтобы не закрывал розетку».

Метрики: успех, число невалидных операций, число правок, время, стоимость.
Приёмка: ≥ 80% успеха, 0 испорченных проектов.

## 5. Гейт 3 — чат в интерфейсе

### C1. Панель чата

Сбоку, не модалка. История, потоковый ответ, контекст проекта, кнопка
«Новый диалог». На мобильном — нижняя шторка.

### C2. Карточки действий

Каждая операция ИИ — карточка: что меняется, параметры, preview, «Применить»
/ «Отменить». Не «ИИ молча сохранил».

### C3. Подсветка изменений

Изменённые объекты подсвечиваются в 3D и на плане; можно нажать «Показать».
До/после — переключатель.

### C4. Apply/undo и версии

Перед пакетом — снимок версии; после — тост «Применено 5 изменений» с
«Отменить». Одно действие — один шаг истории.

### C5. Ограничения

ИИ не сохраняет при ошибках; не удаляет без подтверждения; не выдумывает
размеры; не меняет цены/цех без явного запроса; максимум N операций за пакет.

## 6. Порядок работ

Ориентир для одного разработчика, не гарантия:

1. **Неделя 1–2:** S1–S5 (атомарность, история, идемпотентность, тест
   strict-save, аудит), U2, U4, U5.
2. **Неделя 2–3:** U1 (режимы), U3 (замер 3D + оптимизация), U6.
3. **Неделя 3–4:** A1–A3 (12 операций, tools, preview, ошибки).
4. **Неделя 5:** A4–A5 (сессия, eval), прогон 20 сценариев.
5. **Неделя 6:** C1–C5 (чат, карточки, подсветка, undo).
6. **Неделя 7:** пилот с 3–5 мастерскими, замеры, правки.

## 7. Что не делать до перехода

- Не строить чат раньше контракта операций.
- Не давать ИИ писать сырой `project.json`.
- Не автосохранять действия ИИ без preview и подтверждения.
- Не добавлять новые 3D-фичи, пока нет замеров FPS.
- Не строить CRM/ERP/бухгалтерию.
- Не обещать полную автономность: человек в цикле обязателен.
- Не расширять список модулей, пока 12 операций не покрывают 90% сценариев.

## 8. Чек-лист перехода

- [ ] S1–S5 закрыты, тесты зелёные.
- [ ] U1–U8: мастер-путь ≤ 10 минут, 3D ≥ 30/24 FPS, ошибки с действием.
- [ ] A1–A5: 12 операций, tools, preview, ошибки, сессия, 20 eval ≥ 80%.
- [ ] C1–C5: чат, карточки, подсветка, undo, ограничения.
- [ ] 5 мастерских, 3 «удобно», 1 платный пилот.
- [ ] 0 испорченных проектов за 2 недели.
