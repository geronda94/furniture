# 28 — Архитектура: границы модулей

Статус: рабочий контракт. Цель — чтобы новый код не сваливался в один файл,
а проверки оставались быстрыми и предсказуемыми.

## 1. Слои

```
specs/        данные цеха/фурнитуры/материалов (YAML, MD)
tools/        детерминированный движок (+ CLI-скрипты)
apps/api/     HTTP, сессии, хранение проектов (файлы/Postgres)
apps/web/     UI: состояние, рендер, компоненты
docs/         правила и решения
```

Правило: **движок не знает про HTTP и Vue**, API не считает деталировку сам,
UI не дублирует формулы движка — только отображает `solve`.

## 2. Движок (`tools/furniture_core/`)

| Файл | Ответственность |
|---|---|
| `kitchen.py` | входные параметры → деталировка и состав |
| `parts.py` | детали, кромка, присадка по деталям |
| `assembly.py` | соединения, крепёж, ручки, опоры, пазы |
| `layout.py` | план: стены, проёмы, зазоры, автоплотнение |
| `scene.py` | объёмные коллизии: мебель, декор, двери, ящики |
| `solve.py` | оркестрация: детали + фурнитура + раскрой + смета |
| `cutting.py`, `dxf.py`, `pricing.py` | раскрой, DXF, цены |

Тесты: `tests/golden.py`, `geometry.py`, `features.py`, `layout.py`,
`scene.py`, `api.py`. Любое изменение движка обязано пройти все.

## 3. API (`apps/api/`)

| Файл | Ответственность |
|---|---|
| `main.py` | точка сборки: FastAPI, CORS, подключение роутеров |
| `common.py` | пути, лимиты (rate limit), доступ к проектам, профиль цеха |
| `models.py` | Pydantic-модели запросов |
| `actions.py` | пакетные правки проекта для UI/ИИ (`add_instance`, `set_globals`…) |
| `routers/auth.py` | регистрация, вход, демо-гость, выход |
| `routers/catalog.py` | health, каталог, материалы, цех, фурнитура, цены, гайд |
| `routers/solve.py` | `solve`, `solve/batch`, `validate` |
| `routers/projects.py` | проекты, снимки, расстановка, preflight, strict-PUT, `/cutting` |
| `routers/quickstart.py` | мастер комнаты/проёмов/сценария (`POST /api/quickstart`) |
| `routers/exports.py` | выгрузки XLSX/DXF/SVG (`POST /api/projects/{id}/export/{fmt}`) |
| `storage.py` | файловое/Postgres-хранилище, гости, версии |
| `auth.py` | cookie-сессии, роли |

Правило: тяжёлая работа — в движке; API только проверяет и сохраняет.
Ошибки — `HTTPException` с понятным сообщением; лимиты — `429` + `Retry-After`.

## 4. Состояние UI (`apps/web/src/state/`)

| Файл | Ответственность |
|---|---|
| `defaults.ts` | типы проекта, пресеты модулей, материалы, нормализация JSON |
| `decorCatalog.ts` | сгенерированный из `specs/decor.yaml` справочник декора |
| `geometry.ts` | чистая геометрия плана (без Vue): объёмы, повороты, грани стен |
| `placement.ts` | чистая расстановка: коллизии декора/модулей, свободные места, привязки |
| `project.ts` | реактивный store: выбор, история, solver, сохранение, действия, проверки перемещения/размера |
| `dims/` | размеры: типы, палитра, чистый расчёт внешних расстояний (`outer.ts`) |
| `render3d/handles.ts` | геометрия ручек без состояния рендерера |
| `components/DimOverlay.vue` | SVG-оверлей размеров (линии, стрелки, подписи) |

Правила:

1. Новые **чистые** функции — в `geometry.ts`/`defaults.ts`, не в `project.ts`.
2. `project.ts` не импортирует компоненты и DOM (кроме сохранения/таймеров).
3. Старое API реэкспортируется из `project.ts` — внешние импорты не ломаются.
4. `defaults.ts` не знает про `state` и `derived`.

## 5. Компоненты

- `ModuleWorkbench.vue` — оболочка карточки модуля: шапка, вкладки, левая
  панель, превью. Вкладки, у которых много своей логики, выносятся:
  `ModuleFrontsTab.vue`, `ModuleAssemblyTab.vue`, `ModuleCostTab.vue`.
- Вкладка-компонент получает **данные пропсами** (`params`, `calc`, `inst`),
  действия берёт из store (`updateParams`, `setConnectionOverride`).
- Общие элементы — отдельные компоненты: `DrillingMap`, `PartDetail`,
  `MaterialPanel`, `ModulePreview`, `CameraPad`.

Правило: если блок шаблона > ~60 строк и имеет свои вычисления — это отдельный
компонент, а не ещё одна ветка `v-else-if`.

Полная карта кода и контракт поведения (что нельзя ломать) — `docs/41-code-map.md`.

## 6. Рендер

- `render25d/` — план/развёртки на Canvas 2D (без WebGL), чистые функции
  камеры/сцены/текстур.
- `render3d/babylonScene.ts` — сцена Babylon: меши, материалы, камера,
  коллизии прогулки; не содержит UI-состояния, читает `state` только на входе
  (`sync`). Геометрия декора — `render3d/props/` (реестр билдеров).
- Экспорт: PNG/печать (2×, A3) и SVG (1 единица = 1 мм).

## 7. Тесты и проверки

| Что | Чем |
|---|---|
| Движок | `tests/{golden,geometry,features,layout,scene}.py` |
| API | `tests/api.py` (включая лимиты 429) |
| Сборка | `tsc --noEmit`, `npm run build` |
| UI | `tests/e2e/{smoke,touch,workbench}.mjs` |
| Демо | `tools/validate_project.py` для `demo`, `demo-apartment`, `demo-kitchen-2026` |

Правило: новая функция → минимум один тест; рефакторинг → те же тесты зелёные.

## 8. Мусор и гигиена

- Гостевые копии демо (`projects/demo-<id>/`) — игнор + `prune_guests(7)`.
- `backups/`, `.auth/`, `dist/`, `node_modules/`, `__pycache__/` — в `.gitignore`.
- Временные скрипты проверок не коммитятся: либо тест в `tests/e2e/`, либо
  удаляются.
- Документы нумеруются уникально: `docs/NN-*.md`; ссылки обновляются вместе
  с переименованием.
