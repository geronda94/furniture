## 1. Что уже работает

### Движок (Python, источник истины)
- `tools/furniture_core/` — `config`, `parts`, `cutting`, `kitchen`, `solve`,
  `outputs`, `dxf`. CLI-обёртки: `tools/engine.py`, `tools/kitchen.py`.
- Деталировка, кромка по видимости, присадка System 32, раскрой MaxRects,
  DXF/SVG, `parts.json`, `scene3d.json`.
- **Полки режутся по отсекам**, стойка стоит между дном и крышей и не пробивает
  их; ящик собран без нахлёста деталей (задняя стенка и дно — между боковинами).
- **Конфигурация изделия:** толщина ЛДСП 10/16/18/22, задник ДВП/ЛДСП/картон/нет,
  крыша есть/нет, царги 60 мм (auto/on/off), напольный/навесной, высота цоколя и
  толщина столешницы. Вырезы в столешнице — прямоугольные, идут в присадку.
- **Фасады:** произвольная компоновка сверху вниз (`fronts`): двери и ящики в
  любом порядке и количестве, высота 0 = остаток. Миксы в одном корпусе.
- Тесты: `tests/golden.py` (5 фикстур, хэши), `tests/geometry.py`
  (пересечения объёмов в 3D — 0 на всех конфигурациях) и `tests/features.py`
  (фасады, задник, царги, вырезы, толщина, постформинг, петли, ручки) и
  `tests/api.py` (solve, проекты, действия, версии).

### API
- `apps/api/main.py`: FastAPI, `GET /api/health`, `POST /api/solve`,
  `GET/PUT /api/projects/{id}` (файловые проекты в `projects/<id>/project.json`).
- Запуск: `uvicorn apps.api.main:app --port 8000`.

### Веб (Vue 3 + Vite, чистый CSS)
- `apps/web/`: основной 3D-вьюпорт Babylon.js + план-миниатюра (Canvas 2D),
  ViewCube, орбита/пан/зум, вид от первого лица, Fit (модуль/комната),
  пресеты видов, мобильная раскладка.
- Стены «срез/низкие», проёмы (окна/двери, дверь открывается), материалы и
  процедурные текстуры, тени, режимы «Схема/Реализм», презентация.
- Редактор: модалка «Добавить объект» (каталог мебели + проёмы), drag&drop за
  «захват», привязки 10 мм, запрет пересечения модулей, resize-маркеры на плане,
  undo/redo, автосейв.
- **Поворот модуля** на 90° (кнопка в попапе/инспекторе, клавиша `R`,
  `Shift+R` — обратно); повёрнутый габарит учитывается в привязках и коллизиях.
- **Детали:** клик по двери/ящику → попап элемента с кнопкой «Открыть/Закрыть»,
  слайдером канала, ▶ (проиграть по ключам) и «Ключи». Клик по неподвижной
  детали (полка, боковина) — выделение и размеры в инспекторе.
- **Анимация:** у каждого субобъекта свои каналы и ключи; открывание одной
  двери не открывает соседнюю. В просмотре модуля — редактор каналов/ключей.
- **Просмотр модуля** — вкладка «Детали» единого инспектора: изолированный
  рендер модуля, ракурсы, размеры выбранной детали и **относительные просветы**
  до соседних полок/крышки/дна/перегородок; список элементов по группам.

### Анимация и ключи (унифицированный слой)

`apps/web/src/anim/channels.ts` — единственная модель для всех будущих каналов
(двери, ящики, камера, материалы, что угодно):

```ts
Keyframe = { t, v, ease? }          // время (сек), значение, сглаживание
Channel  = { id, label, unit, min, max, value, keys: Keyframe[] }
ChannelSet = Record<channelId, Channel>
```

- **Субобъект** — подвижная деталь. Ключ: `door:<part>` (каждый лист отдельно)
  или `drawer:<drawer_id>` (корпус + фасад ящика двигаются вместе).
- **Набор каналов** задаётся типом детали (`channelsFor`): дверь — `open` (0…90°),
  ящик — `slide` (0…run мм). Добавить новый тип канала = добавить ветку в
  `channelsFor`; всё остальное (ключи, воспроизведение, рендер) уже общее.
- **Автогенерация ключей** — `defaultKeys(channel, kind)`; вызывается при первом
  открытии/закрытии детали, поэтому анимация готова сразу.
- **Оценка** — `evaluateChannel(channel, t)` / `evaluateSet(set, t)`; рендерер
  получает значения через `PlacedObject.anim`, поэтому о времени и ключах он
  ничего не знает.
- **Хранение** — `instance.anim: Record<ключ, ChannelSet>` в `project.json`,
  сохраняется и восстанавливается вместе с проектом.
- **Воспроизведение** — `playPart(instanceId, part)` (rAF, `animState`), по
  окончании конечное значение фиксируется в `channel.value`.
- **Открытие и закрытие равноправны**: кнопка «Открыть/Закрыть» запускает
  плавный твин значения канала (`runTween`, easeInOut, 0.45 с), а ▶ проигрывает
  дорожку по ключам.

Этот же формат подходит для экспорта таймлайна в Blender/видео: набор ключей —
это уже готовая дорожка.

### Боковая панель: объекты и свойства

- **Дерево объектов** (`Outliner`): корень «Комната» → «Окна и двери» → «Мебель»;
  у объекта раскрываются **субобъекты** (Корпус, Фасады, Ящики, Задняя стенка,
  Столешница и цоколь, Опоры) с размерами. Клик по детали выбирает её.
- **Мультивыделение**: Shift/Ctrl+клик в дереве или в 2.5D, `Ctrl+A` — всё.
  Перетаскивание и стрелки двигают всю группу, `R` поворачивает группу как
  целое вокруг её центра (взаимное расположение сохраняется).
- **Стены**: «Стены» — вложенный список комнаты, у каждой стены миниатюра,
  свои проёмы и настенные предметы; «＋стена» делит выбранную, «＋перегородка»
  добавляет внутреннюю стену, «×» удаляет.
- **Пол/потолок**: отдельные объекты комнаты с материалом и толщиной.
- **Папки/комнаты**: «＋папка» создаёт папку из выделения, «＋комната» — группу
  комнаты, «＋» добавляет выделенные в папку, «×» удаляет папку (объекты остаются).
  Геометрия комнаты (контур/перегородки) — общая на проект; группа лишь
  организует объекты.
- **Свойства** (`ContextProps`) зависят от выбранного узла: комната (габариты,
  стены, материалы), проём (стена, смещение, ширина, Z, состояние), объект
  (имя, W/H/D, двери/ящики/полки, каркас, петли, направляющие, координаты,
  действия, деталировка), деталь (размеры, координаты, канал анимации и ключи),
  папка (название, состав).
  С 2026-10-24 свойства — **единая модалка объекта** (`ObjectModal`): быстрый
  режим у курсора или объектный режим (`ModuleWorkbench`). Устаревшие попапы и
  `InspectorDock` удалены.
- **Проекты** (`ProjectManager`): список файловых проектов, создание пустого,
  переключение; текущий id хранится в `localStorage`. Экспорт проекта в JSON и
  деталировки в CSV — в TopBar/свойствах.
- **Добавление объекта** — модалка (`AddObjectModal`): вкладки «Мебель» и
  «Окна и двери», поиск, фильтр по группам, настройки до добавления. Каталог
  мебели — `MODULE_PRESETS` с полем `group`; проёмы — отдельный тип объекта,
  закреплённый за стеной. Модалка закрывается кликом вне окна и `Esc`,
  добавленный объект сразу выделяется.
- **Координаты**: объект — в комнате (X/Y/Z, мм); проём — относительно стены
  (стена + смещение + ширина + Z); деталь — внутри объекта (показываются).
  **Z залочен** у напольной мебели; кнопка 🔒/🔓 разлочивает (навесная мебель).

### Фурнитура и ящики

- `specs/hardware.yaml` — каталог направляющих: `side_gap`, номиналы длин,
  высота борта. `tools/furniture_core/hardware.py` читает его; движок считает
  короб: **ширина = внутренняя ширина − 2 × зазор**, длина = ближайший номинал,
  влезающий в глубину.
- `GET /api/hardware` отдаёт каталог в веб; в свойствах объекта — селект
  «Направляющие ящиков» (пересчёт при смене).
- Пресет «Тумба с ящиками» (3 ящика) — в «Добавить объект».
- В просмотре модуля — блок «Размеры корпуса» (наружные/внутренние, ЛДСП/ДВП),
  блок «Ящики и фурнитура» (направляющая, зазор, размеры короба и фасада).

### Группировка (объект → субобъекты)

`moduleInfo()` отдаёт `groups`: **Корпус**, **Фасады**, **Ящики**, **Задняя
стенка**, **Столешница и цоколь**, **Опоры**. В просмотре модуля элементы
показываются по группам, с размерами и индикатором «открыто», а клавиши
анимации привязаны к субобъекту, а не к модулю.

### 3D-вьюпорт (Babylon.js)
- **Основной вид — Babylon.js** (`render3d/babylonScene.ts`, `View3D.vue`): PBR-подобные материалы, направленный свет, тени, рёбра, выбор деталей, орто/перспектива, орбита/от лица/полёт.
- **Два режима качества:** «Полный» — тени, рёбра, высокое разрешение; «Каркас» — без теней и фасадов, низкое разрешение (для слабых GPU).
- Выделение — один wireframe-бокс; клик не пересобирает материалы и не включает тяжёлый HighlightLayer.
- Тени обновляются по требованию; материалы и комнатные меши кэшируются/мержатся.
- **Материалы модуля** перекрывают материалы проекта; текстуры (`texture`)
  натягиваются через `diffuseTexture` с масштабом по `texScale`.
- **Canvas 2D** (`render25d/`) остаётся для плана, миниатюр и превью деталей;
  архивный старый вьюпорт удалён.
- **Порядок отрисовки**: топологическая сортировка коробок по «кто за кем».
- **Вплотную стоящие модули**: грани, целиком погружённые в объём соседа,
  отсекаются (иначе боковина дальнего модуля просвечивала между фасадами).

## 2. Как запускать

```bash
# движок
python3 tools/kitchen.py --sections "850:2:0:Тумба" --out projects/demo

# проверки
python3 tests/golden.py        # эталоны
python3 tests/geometry.py      # пересечения деталей
cd apps/web && npx tsc --noEmit && npm run build

# API (порт 8000)
uvicorn apps.api.main:app --port 8000

# веб (порт 5173, прокси /api → 8000)
cd apps/web && npm run dev
```

## 3. Известные ограничения

- `openpyxl` не установлен → `parts.xlsx` молча не создаётся (CSV/JSON есть).
- `tsc` не проверяет `.vue` (нет `vue-tsc`); ошибки в SFC видны только в рантайме.
- Координаты субобъектов показываются, но не редактируются: их считает движок
  (правка сломала бы деталировку). Управление — параметрами модуля.
- Удаление субобъекта = уменьшение параметра (полки/двери/ящики), произвольную
  деталь удалить нельзя.
- Стойки добавляются только под двери (`doors > 0`); для чисто ящичных модулей
  внутренних стоек нет.
- Вырезы только прямоугольные; произвольные контуры/скругления не поддержаны.
- Цены/смета, каталог декоров, версионирование проектов — не сделаны.
- Комнаты как отдельные группы — через папки; автоматической привязки
  «комната → свои стены/мебель» пока нет (стены общие на проект).
- Blender-пайплайн есть (`tools/blender_build.py`), но кнопки рендера из веба нет.

## 10. Управление камерой и полями (2026-10-25)

- **3D (Babylon):** плавный wheel-зум (`wheelDeltaPercentage`), зум к курсору,
  инерция, спокойнее вращение и панорама; два пальца — панорама + пинч
  (`multiTouchPanAndZoom`, `useNaturalPinchZoom`). Второй палец отменяет
  перетаскивание модуля и отдаёт жест камере.
- **План (Canvas 2D):** пинч двумя пальцами с сохранением точки под пальцами;
  wheel-зум с экспоненциальным сглаживанием (не рывками); панорама одним
  пальцем/ПКМ.
- **Числовые поля:** компактные `NumField` (132 px, кнопки ± уже), числовые
  input ограничены по ширине; на touch — крупнее по высоте, но не растянуты
  на всю панель.


## 11. Переменные материалов (2026-10-25)

Материалы проекта — это fallback по ролям. Поверх них работают **глобальные
переменные материалов**: именованный декор + набор частей + охват.

- Части: каркас, боковины, полки, перегородки, двери, фасады ящиков, корпуса
  ящиков, задник, столешница, цоколь, опоры.
- Охват: все модули / только напольные / только навесные.
- Переменная может применяться к нескольким частям сразу (например, каркас +
  боковины + перегородки).
- Приоритет: материалы проекта → переменные `all` → переменные `floor/wall`
  → материал конкретного модуля. Ниже в списке — выше приоритет внутри охвата.
- «Базовый набор» создаёт переменные для напольного/навесного корпуса,
  фасадов, ящиков, полок, задника, столешницы, цоколя и опор.
- UI: «Проект → Переменные»; из вкладки «Материалы» модуля — кнопка
  «Глобальные переменные…». Данные лежат в `project.materialVars`.
