# 43 — Полное управление через ИИ-чат

Дата: 2026-11-02. Связано: `docs/42-ai-integration.md`, `docs/41-code-map.md`,
`docs/20-layout-rules.md`.

## 1. Цель

Человек описывает задачу словами — ИИ строит помещение и мебель теми же
операциями, что и интерфейс: комната и план, стены/перегородки, окна/двери,
розетки/полки/зеркала, модули (габариты, створки, ящики, полки, фасады,
материалы, фурнитура), раскладка, проверка, смета и деталировка, вид и
камера, создание/открытие проектов.

Ограничение остаётся одно: ИИ **не пишет сырой `project.json`**. Все
изменения — типизированные инструменты → `preview` → подтверждение человека →
`actions strict` (один undo).

## 2. Что умеет чат

| Область | Инструменты | Побочный эффект |
|---|---|---|
| Проекты | `project_list`, `project_open`, `project_create`, `project_quickstart`, `project_delete`, `rename_project` | новый проект открывается, диалог переносится |
| Комната | `resize_room` (w/d/h/wallT, `rect`/`l`, произвольный `outline`), `set_room` (пол/потолок) | пересборка контура, подгонка проёмов и предметов |
| Стены | `add_partition`, `update_partition`, `delete_partition` | удаление с проёмами/предметами запрещено |
| Проёмы | `add_opening`, `update_opening`, `delete_opening` | проверка стены, пересечений, мебели и зоны подхода |
| На стенах | `add_wall_item`, `update_wall_item`, `delete_wall_item` | авто-место, проверка проёмов/мебели |
| Мебель | `add_module`, `update_module`, `duplicate_module`, `delete_module` | коллизии проверяются до сохранения |
| Декор | `add_decor`, `update_decor`, `delete_decor` | авто-место в комнате |
| Материалы | `set_materials`, `set_module_material`, `set_globals` | проект или модуль, роль материала |
| Раскладка | `normalize_layout`, `fix_issues` | прижать/уплотнить, физические фиксы |
| Папки/зоны | `add_folder`, `update_folder`, `delete_folder` | группировка модулей |
| Чтение | `validate`, `get_quote`, `get_parts` | ничего не меняют |
| Вид | `camera_set`, `camera_focus`, `selection_set`, `select_all`, `view_mode`, `walls_mode`, `dims_set`, `ui_panel`, `toggle_part`, `scene_screenshot` | панели, выделение, проверка открывания |
| История/файлы | `undo`, `redo`, `save`, `export_file` (КП PDF, SVG, DXF, XLSX), `version_create`, `version_list`, `version_restore` | откат/сохранение/версии/скачивание |

Полный каталог с JSON Schema и правилами — `GET /api/ai/tools`
(`apps/api/ai_tools.py`).

## 3. Как это устроено

```
AiChatPanel.vue
  ├─ ai/context.ts   снимок: камера, выделение, комната+стены, модули+материалы,
  │                  декор, ошибки, смета
  ├─ ai/tools.ts     клиентские инструменты: вид, проекты, чтение, файлы
  └─ serverActions() серверные инструменты → {op:…} для /preview и /actions
                         │
              apps/api/actions.py + room.py + placement.py + fixes.py
                         │
                    furniture_core (геометрия, валидаторы, нормализация)
```

- Клиент выполняет инструмент, возвращает результат модели как `role: tool`.
- Серверные инструменты только **накапливаются** в пакет; после ответа модели
  клиент делает `/preview`, показывает diff/ошибки/цену, затем по кнопке
  «Применить» — `/actions {commit, strict}`.
- После применения проект перезагружается с сохранением камеры и выделения;
  первый изменённый модуль подсвечивается, в чат пишется число изменений.
- `project_create`/`project_quickstart` создают проект на сервере и возвращают
  `switchTo`; панель переносит историю диалога в новый проект и открывает его.
- `validate`/`get_quote`/`get_parts` возвращают данные модели (и краткую
  подпись человеку) — без предпросмотра.
- Удаление данных — только с `confirm=true` (человек явно попросил).
- За пакет — не больше 12 операций; большая задача делится на шаги
  «комната → мебель → материалы → проверка».

## 4. Координаты и параметры

- Единицы — миллиметры, углы — градусы. Комната: x вправо, y в глубину
  плана, z вверх от пола.
- У модуля `x/y` — левый-передний угол подошвы при `rot=0`; модуль растёт по
  `+x` на `W` и по `+y` на `D`, поворот вокруг этого угла. У декора `x/y` —
  центр.
- Стены нумеруются с 0: сначала стены контура, затем перегородки.
- Параметры модуля описаны в `MODULE_PARAMS` (`ai_tools.py`) и уходят модели
  в системном промпте: W/H/D, mount, doors/drawers/shelves/dividers,
  plinthH/worktopT, fronts, frame, facadeMaterial, handle, runners, cutouts,
  edges и т.д.

## 5. Проверки и безопасность

- Новые операции валидируются до сохранения: проём не выйдет за стену и не
  встанет на мебель; перегородку с проёмами не удалить; `update_instance`
  проверяет геометрию; `resize_room` подгоняет проёмы/предметы или понятно
  отказывает.
- `preview` остаётся атомарным: ошибка в одной операции отменяет весь пакет.
- `actions strict` не сохраняет проект с `errors > 0`.
- `fix_issues` применяет только безопасные фиксы (высоты, цоколь, ширина
  створок/ящиков, стойка, позиция), остальное возвращает в `skipped`.
- Модель не видит ключей и не ходит в БД; сервер — единственный источник
  валидации и цен.

## 6. Тесты

- `tests/api.py` — resize/L-комната, проёмы и их ограничения, перегородки и
  запрет удаления с проёмами, копия модуля, материал модуля, папки,
  переименование, diff комнаты/папок, `normalize_layout`, `fix_issues`.
- `tests/e2e/ai-design-flow.mjs` — чат создаёт проект, строит комнату с окном,
  добавляет модули и материалы, применяет пакет.
- `ai-chat-flow` — базовый цикл tool-call → preview → apply.

## 7. Eval на живой модели

- `tools/ai_eval.py` — 20 сценариев: комната/окно/L-форма, кухонный ряд,
  шкаф до потолка, ящики, фасад, ширина, исправление ошибок, смета,
  перегородка с дверью, розетка, мойка с вырезом, навесной, высота комнаты,
  входная дверь, два материала, копия, гардероб из 3 секций, вытяжка,
  удаление, Г-комната.
- Прогон **2026-11-03, DeepSeek**: **20/20**, испорченных сохранений **0**;
  4 сценария потребовали автоисправления предпросмотра. Отчёт —
  `docs/ai-eval-report.md`.
- Автоисправление: если предпросмотр вернул ошибки, клиент показывает их
  модели и просит полный исправленный пакет (до 2 раз) — человек видит уже
  исправленный вариант или честный отказ.
- Запуск: `python3 tools/ai_eval.py` (API поднят, `AI_API_KEY` задан).

## 8. Что осознанно вне чата

Служебные и «косметические» разделы остаются в интерфейсе: загрузка текстур,
отделка (finishes), сохранённые виды, настройки цен/рынков, тур, презентация,
фото/план как черновик. Их можно добавить следующими
инструментами без изменения архитектуры — тем же путём «инструмент →
preview → apply».

Также вне v1: материал **отдельной детали** (part-level overrides) — сейчас
чат меняет материал модуля целиком; для деталей есть UI.
