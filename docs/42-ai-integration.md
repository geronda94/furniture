# 42 — Как встроить ИИ: контекст, инструменты, чат

Дата: 2026-11-02. Связано: `docs/32-pre-ai-readiness.md`,
`docs/22-ai-generation-validation.md`, `docs/41-code-map.md`,
`docs/business/strategy/FURNITURE_BUSINESS_PLAN.md` §9.

## 1. Цель и что ждёт бизнес-план

ИИ — не отдельный продукт, а слой управления **существующим проектом**:

- 5 команд на старте: шире/уже, заполнить зазор, поднять полку,
  добавить/удалить модуль, поменять материал;
- 10 команд на гейте, 8/10 без поломок, 0 невалидных сохранений;
- preview/diff «было → стало», откат, подсветка изменённого;
- чат: сообщение → план → предпросмотр → применить/отменить;
- фото/план как черновик;
- визуализация вместимости v1 (кастрюли/пальто/свитера простыми объёмами);
- 20 eval-сценариев, метрики: успех, невалидные действия, правки, время.

ИИ **не** пишет сырой `project.json` и **не** сохраняет без проверки.

## 2. Что уже есть (фундамент)

| Компонент | Где | Статус |
|---|---|---|
| Каталог инструментов (JSON Schema) | `apps/api/ai_tools.py`, `GET /api/ai/tools` | ✅ |
| Предпросмотр пакета: diff, ошибки, цена, без сохранения | `POST /api/projects/{id}/preview` | ✅ |
| Пакетные правки (6 операций) + strict | `POST /api/projects/{id}/actions` | ✅ |
| Инструкция/правила для агента | `GET /api/ai/guide` | ✅ |
| Снимок контекста сцены | `apps/web/src/ai/context.ts` | ✅ |

## 3. Архитектура

```
 Браузер
 ┌──────────────────────────────────────────────────────────┐
 │ AiChatPanel.vue                                          │
 │  сообщения, карточки действий, diff, «Применить/Отменить»│
 │        │                                                 │
 │        ├── ai/context.ts  → снимок сцены (камера, выбор,  │
 │        │                    комната, объекты, ошибки)     │
 │        ├── ai/tools.ts    → камера/выделение/вид/размеры  │
 │        └── api.ts         → /api/ai/chat (SSE),           │
 │                             /preview, /actions strict     │
 └───────────────┬──────────────────────────────────────────┘
                 │
        ┌────────▼─────────┐
        │ apps/api         │
        │ /api/ai/tools    │  JSON Schema
        │ /api/ai/chat     │  LLM-прокси + tool-calls
        │ /preview         │  память: diff/ошибки/цена
        │ /actions strict  │  сохранение только без ошибок
        └────────┬─────────┘
                 │
        ┌────────▼─────────┐
        │ furniture_core   │  деталировка, раскрой, валидация
        └──────────────────┘
```

**Оркестрация v1 — на клиенте.** Браузер отправляет контекст + историю,
получает от LLM текст/tool-calls, сам выполняет клиентские инструменты и
вызывает серверные `/preview`, `/actions`. Это сохраняет локальное состояние
проекта (несохранённые правки) и позволяет стримить ответ. Сервер остаётся
источником валидации и цен.

**Оркестрация v2 (позже)** — серверная сессия дизайна (`docs/32` A4),
когда нужны фоновые задачи, фото и несколько клиентов.

## 4. Контекст сцены

`buildSceneContext(renderer)` отдаёт компактный JSON:

- `app`: проект, ревизия, режим, стены, размеры, презентация, мастер-режим;
- `camera`: `alphaDeg`, `betaDeg`, `radius`, `target`, проекция, режим,
  качество, стены, чертёж;
- `selection`: `module` (полные параметры, габарит, позиция), `part`
  (индекс, название, размер, связи «до соседа»), `wall`, `opening`, `prop`,
  `room` или `none`;
- `room`: размеры, контур, перегородки, проёмы, предметы на стенах;
- `project`: компактные модули (id/имя/позиция/поворот/W-H-D/mount/габарит),
  декор, папки, globals, счётчики, флаг усечения;
- `issues`: число ошибок/предупреждений + до 20 пунктов с `fix` и
  `auto_fixable`.

Правила:
- выбранный объект — полно, остальные — компактно;
- большие проекты усекаются (80 строк), модель может запросить детали
  инструментом;
- снимок канваса **не** кладётся в каждый запрос: только по кнопке
  «Показать сцену» или когда модель просит `scene_screenshot`;
- контекст — это данные, не команды: действия только через инструменты.

## 5. Инструменты

### Серверные (меняют проект)

Реализованы: `add_module`, `update_module`, `delete_module`, `add_opening`,
`set_room`, `set_globals`, `normalize_layout`, `preview_actions`, `validate`.

Добавлены: `update_opening`, `delete_opening`, `add_wall_item`,
`update_wall_item`, `delete_wall_item`, `add_decor`, `update_decor`,
`delete_decor`, `set_materials`.
Планируются: `apply_template`, `quote`, `export`.

Правило: каждая операция — типизированная, с JSON Schema, предусловиями и
человеческим сообщением об ошибке (`docs/32` A1).

### Клиентские (не меняют проект)

`camera_set`, `camera_focus`, `selection_set`, `view_mode`, `walls_mode`,
`dims_set`, `scene_screenshot`.

Они выполняются в браузере через `runAiTool(name, args, renderer)`.

### Пайплайн инструмента

```
LLM tool_call
  → клиент: client tool? выполнить сразу
  → серверный: preview_actions (commit=false)
       → diff, errors, cost
       → карточка «было/стало»
       → человек: Применить / Отменить
       → actions {commit:true, strict:true}
       → один undo + подсветка изменённых объектов
```

- Максимум 8 операций за пакет.
- Удаление — только с подтверждением.
- При `errors > 0` сохранение отклоняется; модель получает ошибки и
  предлагает fix.
- Один пакет = один шаг истории (`pushHistory('ИИ: …')` / снимок версии).

## 6. Чат-панель

- Сбоку, не модалка; на телефоне — нижняя шторка.
- Шапка: проект, контекст («Выделено: Мойка 800 · вид Изо»), кнопка
  «Показать сцену» (прикрепляет JPEG), «Новый диалог».
- Сообщения: текст, поток, tool-call карточки, diff, стоимость, ошибки.
- Быстрые команды: «Шире на 10 см», «Заполнить зазор», «Поднять полку»,
  «Добавить модуль», «Сменить фасад».
- Ответ с изменениями заканчивается карточкой:
  «Будет: +1 модуль, смета +€420, ошибок 0» → **Применить** / **Отменить**.
- После применения: тост «Применено N изменений» + «Отменить»; первый
  изменённый объект выделяется (пунктирная рамка подсветки), в чат пишется
  «Изменено объектов: N».
- История диалога хранится на проект в localStorage; кнопка «＋» — новый
  диалог. Секретов в истории нет.

## 7. LLM-провайдер

- По умолчанию — **DeepSeek**: `AI_BASE_URL=https://api.deepseek.com`,
  `AI_MODEL=deepseek-chat`, ключ `DEEPSEEK_API_KEY` (или `AI_API_KEY`).
- OpenAI-совместимый API: `AI_BASE_URL`, `AI_API_KEY`, `AI_MODEL`,
  `AI_MAX_TOKENS`, `AI_TIMEOUT`.
- Подходит OpenAI, OpenRouter, локальный Ollama (`/v1`).
- Стриминг SSE, tool-calling, JSON-schema tools.
- Системный промпт собирается из `/api/ai/guide` + `/api/ai/tools` +
  правила безопасности; контекст — отдельным сообщением.
- Лимиты: максимум токенов на запрос, стоимость на пользователя/проект,
  rate limit; при отсутствии ключа — понятное «ИИ не настроен», а не падение.
- Секреты только на сервере; браузер не видит ключ.

## 8. Безопасность и качество

- Никаких сырых JSON-правок от модели; только allowlist инструментов.
- `strict=true` на каждом сохранении; preview обязателен для пакета >1.
- Подтверждение удаления и необратимых действий.
- Аудит: кто/когда/какие операции/ошибки/что применено (`docs/32` S5).
- Идемпотентность пакета (`request_id`).
- Ограничение контекста: не отправлять всю деталировку и текстуры.
- Фото/план — только с согласия; не хранить лишние персональные данные.

## 9. Eval (20 сценариев из бизнес-плана)

Кухня 3×4 с окном и мойкой; гардероб 2.5 м в три секции; расширить модуль
№3; заполнить зазор 10 см; добавить/поднять полку; сменить фасад на МДФ;
удалить пенал; заменить двери на ящики; проверить открывание; холодильник в
угол; убрать шкаф с окна; розетка за тумбой; гардероб до потолка; штанга;
столешница; глубина навесных; зазоры 2–3 мм; черновик по фото/плану.

Метрики: успех, число невалидных действий, число правок, время, стоимость.
Гейт: ≥ 8/10 без поломок, 0 испорченных проектов.

## 10. Порядок внедрения

1. **Сделано:** контекст сцены, клиентские инструменты, `/api/ai/tools`,
   `/preview`, strict actions, API-тесты.
2. **Сделано (v1):** `POST /api/ai/chat` с DeepSeek, панель чата, tool-calls,
   предпросмотр, apply/undo; 5 базовых команд.
3. **Следующее:** стриминг, подсветка изменений, больше операций
   (стены/декор/материалы), фото/план.
4. Фото/план как черновик (vision + `add_module/update_module`).
5. Вместимость v1 (простые объёмы внутри модуля).
6. 20 eval-сценариев, замеры, пилот.

## 11. Чего не делать

- Не строить чат раньше контракта операций — контракт уже есть.
- Не давать модели писать проект целиком.
- Не автосохранять без preview/подтверждения.
- Не обещать автономность: человек в цикле.
- Не смешивать ИИ-косты с бесплатным тарифом без лимитов.
