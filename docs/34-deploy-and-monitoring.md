## 1. Почему это появилось

29.10 прод (`5176.it2b.top`) висел на «Проверяем сессию…» **26 часов**:
образ API был собран до добавления `reportlab`, а compose запускал uvicorn
с `--reload` и монтировал исходники. Каждый релоад падал на импорте
`routers/exports.py → pdf.py`, воркер не поднимался, `/api/health` молчал.
Сайт при этом отдавался статикой и выглядел живым, а фронтенд был сборкой
от 28.10 — без QuickStart и «Готового проекта».

Вывод: «собрать образ руками и посмотреть глазами» — не деплой. Нужен
воспроизводимый шаг с проверкой и откатом, и сторож, который замечает
проблему раньше цеха.

## 2. Как теперь устроено

| Что | Файл | Поведение |
|---|---|---|
| Прод-режим | `compose.yaml` | uvicorn **без** `--reload`; перезапуск только деплоем |
| Режим разработки | `compose.dev.yaml` | `docker compose -f compose.yaml -f compose.dev.yaml up -d` — с `--reload` |
| Деплой | `tools/deploy.sh` | тесты → метка `:previous` → сборка → перезапуск → healthy → smoke → откат при провале |
| Сторож | `tools/health_watch.sh` | каждые 5 минут: контейнеры + публичный `/api/health`; один перезапуск, потом алерт |
| Таймер | `tools/systemd/furniture-health.{service,timer}` | установка `tools/install-monitor.sh` |
| Логи | `/var/log/furniture-deploy.log`, `/var/log/furniture-health.log` | кто, когда, что перезапустили |

### Деплой

```bash
cd /root/projects/furniture
git pull                 # код
tools/deploy.sh          # тесты, сборка, перезапуск, проверка, откат
```

Параметры: `--skip-tests` (только сборка и выкладка), `--no-build`
(перезапуск текущих образов). При любом провале — на health, smoke или
сборке — стек возвращается на образы `:previous`, скрипт выходит с ошибкой
и пишет причину в лог. Долгие e2e-тесты в деплой не входят: они в CI.

### Мониторинг

```bash
tools/health_watch.sh --check   # только проверить, код 1 при проблеме
tools/health_watch.sh           # проверить и починить (перезапуск)
tools/install-monitor.sh        # systemd-таймер каждые 5 минут
tools/install-monitor.sh --off  # выключить
```

Правила сторожа:

- `api`/`web`/`db` не `healthy` или публичный `/api/health` не 200 →
  один `docker restart` проблемного контейнера;
- после перезапуска снова плохо → алерт, без цикла рестартов;
- не больше 2 перезапусков на сервис за 30 минут (защита от «лечения»
  настоящей ошибки кода);
- алерт в Telegram опционален: `/etc/furniture-monitor.env` с
  `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Без них — только лог.

Проверено 29.10: остановленный `furniture-api-1` поднят сторожем за ~20 с;
искусственный сбой health в деплое привёл к откату на `:previous`, стек
остался живым.

## 3. Что осталось по инфраструктуре

- **Сборка в CI.** GitHub Actions собирает код, но не образы; после
  изменения `requirements.txt`/`Dockerfile` деплой обязателен. Идеально:
  публикация образов в registry из CI и `deploy.sh --pull`.
- **Алерт без Telegram.** Пока токена нет, о падении узнаём из лога или от
  людей. 5 минут работы: завести бота и чат, положить файл.
- **Бэкап БД.** ✅ Ежедневный `pg_dump` в 03:40 (`furniture-backup.timer`),
  проверка архива и заголовка дампа, ротация 14 дней; `tools/backup_db.sh
  --check` для контроля. Осталось: проверка восстановления в отдельную БД.
- **`--reload` в проде** убран, но `.:/app` в compose остаётся: код на
  проде = рабочая копия. Для настоящего прода — образ без монтирования.
- **Реальные замеры телефона** — `docs/31-device-checklist.md`, это A1 из
  `docs/33`.
