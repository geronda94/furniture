# 22 — ИИ-генерация: валидация сцены и запрет пересечений

Статус: ✅ базовая проверка внедрена; расширять по мере появления новых типов
объектов. Связанные документы: `docs/20-layout-rules.md`,
`tools/furniture_core/scene.py`, `tests/scene.py`.

## 1. Что было не так

ИИ-агент собирал `project.json` вручную и проверял только план модулей
(`layout.py`). Из-за этого проходили:

- корпус/столешница в стене или в проёме;
- цоколь выше корпуса и «под полом»;
- декор (растения, ТВ, сантехника) внутри мебели/стен;
- открытая дверь фасада бьёт в дверь комнаты или в соседний модуль;
- кухня/гардероб с разрывами между корпусами;
- ТВ/кресло/ванна пересекаются друг с другом.

## 2. Модель проверки

Любой объект — это **объём**:

| Тип | План | Высота |
|---|---|---|
| Модуль | повёрнутый прямоугольник `x,y,W,D` | `z .. z + plinthH + H + worktopT` |
| Декор | повёрнутый прямоугольник `x,y,w,d` от центра | `z .. z+h` |
| Стена | тело `[-wallT, 0]` вдоль нормали | 0..`room.h` |
| Проём | тело + зона подхода/открывания | `z0..z1` |
| Дверь фасада | зона перед модулем шириной створки | низ двери..верх двери |

Пересечение считается по SAT в плане + пересечение интервалов по Z.
Допуск на касание — 1,5 мм; всё, что глубже, — ошибка. «Текстура» — это
поверхность тела, поэтому запрет входа в тело = запрет входа в текстуру.

## 3. Правила

1. `0 <= plinthH < H`; фактическая высота не ниже 0 и не выше `room.h`.
2. Столешница выступает вперёд на 20 мм — этот выступ тоже проверяется.
3. Непрерывный ряд (кухня/гардероб/шкафы) — зазор 0 мм. Разрыв > 2 мм —
   ошибка; исключение — разрыв на двери/окне.
4. Декор — твёрдое тело; ковёр не объём для мебели, но не выходит за комнату.
5. Дверь фасада при открывании не задевает стену, проём, мебель, декор и
   другую створку.
6. Навесной модуль не перекрывает окно по Z; ручки — по правилам высоты.
7. Проект с `errors > 0` нельзя сохранять/отдавать.

## 4. API и пайплайн

```
python3 tools/validate_project.py <project.json>   # локальная проверка
POST /api/solve/batch               # несколько модулей одним запросом
GET  /api/projects/{id}/layout      # план + объёмные коллизии
POST /api/projects/{id}/layout/normalize  # fixDecor=true: развести декор
PUT  /api/projects/{id}?strict=1    # 422 при errors > 0
POST /api/projects/{id}/actions     # {commit:true, strict:true}
```

Тяжёлые эндпоинты (`solve`, `solve/batch`, `validate`, `preflight`,
`layout`, `normalize`, `PUT`) ограничены по запросам в минуту на
пользователя (анонимно — на IP): при превышении — `429` и заголовок
`Retry-After`. Пороги — env `RATE_SOLVE_PER_MIN`, `RATE_BATCH_PER_MIN`,
`RATE_VALIDATE_PER_MIN`, `RATE_LAYOUT_PER_MIN`, `RATE_NORMALIZE_PER_MIN`,
`RATE_SAVE_PER_MIN` (по умолчанию 240/120/240/300/60/180). Агенту при
`429` нужно подождать и повторить, а не менять запрос.

Пайплайн агента:

1. Прочитать комнату/проёмы/зону.
2. Поставить ряд: задняя грань на стене, фасад в комнату, корпуса вплотную.
3. Высокие модули — в конец ряда; навесные — не на окно/дверь.
4. Декор — только в свободные зоны; проверить его как мебель.
5. `normalize` (предпросмотр) → `normalize commit`.
6. `GET /layout` → `errors = 0`.
7. `PUT ?strict=1` / `actions strict:true`.
8. Только после этого — `solve` и выдача человеку.

  параметры и проверить газовые патроны.

- Валидация 3D-моделей фурнитуры, когда появятся `model3d`.
