# 31 — Проверка на реальном устройстве (телефон/слабый ноутбук)

Физический стенд и замеры FPS здесь не автоматизируются: нужен реальный
девайс. Ниже — короткий протокол, чтобы проверка занимала 10–15 минут.

## 1. Что открыть

1. Телефон в той же сети, что сервер: `https://<домен>/` (или LAN-адрес).
2. Для HUD производительности: `https://<домен>/?perf=1` — сверху слева
   FPS / память / число мешей.
3. Демо: «Посмотреть демо» или «Быстрый старт» (кухня).

## 2. Сценарий (5 минут)

| Шаг | Что проверить | Норма |
|---|---|---|
| Открыть демо | первый кадр 3D | ≤ 8 с на 4G/среднем телефоне |
| Вращение одним пальцем | сцена идёт за пальцем, без рывков | ≥ 24 FPS |
| Джойстик вверх/вправо | идёт по взгляду, не инвертирован | — |
| «Прогулка» | вход в комнату, стены не просвечивают | ≥ 24 FPS |
| Пройти в стену/шкаф | камера упирается и скользит | без прохода сквозь |
| Развёртки стен | открываются, зум колесом/пинчем | ≤ 2 с |
| Перетащить розетку | двигается по X/Z | без лагов |
| «Готовый проект» | сводка и статус «Готов к производству» | ≤ 2 с (раскрой — до 10 с) |
| PDF КП / XLSX | скачиваются и открываются | — |

## 3. Что записать

- Модель телефона, ОС, браузер.
- FPS в покое и при вращении (HUD).
- Память (HUD, МБ) после 2 минут работы.
- Время первого кадра и открытия развёрток.
- Замечания по жестам (что именно неудобно).

Результат — в `docs/14-worklog.md` (секция Z) и, если есть регресс,
задача в `tasks/backlog.md`.

## 4. Автоматические проверки рядом

- `tests/e2e/smoke.mjs` — ПК + мобильный viewport (headless).
- `tests/e2e/touch.mjs` — направление свайпа/джойстика, границы комнаты.
- `tests/e2e/perf.mjs` — HUD/FPS в headless (для регресса логики, не для
  реального GPU).
- `tests/e2e/workbench.mjs`, `library.mjs`, `quickstart.mjs`,
  `exports.mjs`, `wallitems.mjs`.

## 5. Известные ограничения песочницы

- Software GL даёт 1–3 FPS — цифры не показательны.
- Нет реального multi-touch и инерции пальца; проверяется только логика.
