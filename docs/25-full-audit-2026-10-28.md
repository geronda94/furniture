# 25 — Полный аудит софта и работ (2026-10-28)

> Статус исправлений: `docs/26-remediation-plan.md`. Часть P0/P1 уже закрыта
> после этой проверки.

Аудит проведён по четырём осям: **удобство/интуитивность**, **точность
расчётов**, **соответствие стандартам**, **надёжность/безопасность**.
Проверялись код, API, данные, документация и публичный контур.

## 0. Итоговая оценка

| Направление | Оценка | Комментарий |
|---|---|---|
| Расчётное ядро | **8/10** | Детерминировано, golden/geometry/features зелёные; есть смысловые расхождения H и документации |
| Валидация сцены | **8/10** | Стены, проёмы, двери, декор, ящики, цоколь; не все объекты и не все углы |

| Производительность | **5/10** | `normalize_scene` 7 с; 3D/бандл тяжёлый; lazy solver частичный |
| Безопасность | **6/10** | Cookie не Secure, гости без лимита, fallback APP_SECRET |

## 3. Находки

### P0 — блокеры перед активной эксплуатацией

#### P0-1. `normalize_scene` работает 7 секунд
- **Факт:** на демо-квартире с одним конфликтом — `7.10 s`, 2 перемещения.
- **Причина:** для каждого кандидата вызывается полный `validate_scene`,
  а не локальная проверка коллизий.
- **Риск:** запрос «Уплотнить/развести» блокирует API и UI; на 50 модулях
  будет хуже.
- **Решение:** кэшировать препятствия (стены/проёмы/мебель/декор/двери) и
  проверять кандидата локально; полный `validate_scene` — один раз в конце.
  Цель: < 300 мс.

#### P0-2. UI всё ещё может сохранить невалидный проект
- **Факт:** `saveProject()` делает обычный `PUT`; strict-проверка есть только
  у `PUT ?strict=1`/`actions strict`. Индикатор `расстановка` обновляется
  после сохранения.
- **Риск:** пользователь/агент видит «ок» до проверки или сохраняет проект
  с мебелью в стене/декоре; «всегда валидировать» не выполнено для UI.
- **Решение:** перед `PUT` вызывать `GET /layout` (debounce) и блокировать
  сохранение при `errors > 0`, либо сделать strict обязательным для UI,
  а промежуточные состояния хранить локально.

#### P0-3. Production cookie не `Secure`
- **Факт:** `.env` (`COOKIE_SECURE=0`), `compose.yaml` default `0`;
  публичный контур работает по HTTPS.
- **Риск:** cookie сессии может уйти по HTTP при ошибке редиректа/смешанном
  контуре.
- **Решение:** для production `COOKIE_SECURE=1`; в dev — 0 только локально.
  Дополнительно проверить `APP_SECRET` (в compose есть fallback
  `dev-furniture-secret-change-me`).

### P1 — серьёзные, но не блокирующие

#### P1-1. `H` — это высота корпуса, а не всего модуля
- **Факт:** `solve()` отдаёт `dims.outer.H = 720`, но фактический верх
  напольного модуля = `plinthH + H + worktopT` = `100 + 720 + 38 = 858`.
  UI показывает `800×720×560`, статусбар — `H=720`.
- **Риск:** заказчик/ИИ думает, что модуль 720 мм, а он 858 мм; ошибки
  под окнами, столешницами, навесными.
- **Решение:** в API добавить `H_total`, `plinth_h`, `worktop_t`; в UI
  подписывать «корпус / полная высота».

#### P1-2. Задняя стенка: документация и движок расходятся
- **Факт:** `docs/01-design-rules.md` — `(W−2) × (H−2)`;
  `kitchen.py` — `Part("Задняя стенка", 1, W, H)` и `_box(... W, ..., H)`.
- **Риск:** цех/ИИ посчитает 598×718, движок даст 600×720.
- **Решение:** зафиксировать стандарт (набивная внахлёст = W×H или
  вкладная = W−2/H−2), обновить docs и golden.

#### P1-3. Развёртки стен без зума/панорамы
- **Факт:** `WallView.vue` только fit + выбор; длинная стена 9000 мм
  отображается мелко, подписи могут накладываться; нет `wheel/pan`.
- **Риск:** на длинной кухне размеры не читаются, режим неудобен.
- **Решение:** wheel-зум к курсору, перетаскивание, кнопка «вписать»,
  перенос подписей, печать/PDF/SVG.

#### P1-4. Панель «Расстановка» показывает сырые коды
- **Факт:** `codeLabel` в `LayoutPanel.vue` знает только `in-wall`, `outside`,
  `opening`, `overlap`, `gap`, `front-to-wall`. Новые `prop-*`, `door-*`,
  `plinth`, `below-floor`, `above-ceiling`, `wallitem`, `drawer-*` выводятся
  как код. Ошибки декора не кликабельны (`showIssue` только `instance`).
- **Риск:** пользователь не понимает, что делать.
- **Решение:** расширить словарь, кликать/фокусировать декор, показывать
  иконку и рекомендацию.

#### P1-5. Ленивая загрузка всё ещё считает всё на сильном ПК
- **Факт:** `solveInitial` сначала решает комнату, но через 1.2 с запускает
  `solveAll`; `onlyRoom` по умолчанию false (включается только на CPU ≤ 4).
  Batch-solve API нет; кэш `derived` не освобождается.
- **Риск:** «полная ленивая загрузка» не достигнута; память растёт.
- **Решение:** не запускать фон без явного запроса, добавить
  `POST /api/solve/batch`, TTL/очистку `derived` для скрытых зон, замер
  20/50 модулей.

#### P1-6. Индикатор расстановки может быть устаревшим
- **Факт:** `scheduleLayoutCheck` вызывается после сохранения/загрузки;
  `checkLayout` не имеет sequence-token; несколько запросов могут
  перезаписать свежий старый.
- **Риск:** «расстановка: ок» при уже изменённой сцене.
- **Решение:** проверять после каждого `touch` с debounce 1–2 с, хранить
  версию проекта/sequence, отбрасывать устаревшие ответы.

#### P1-7. Нет E2E/визуальных тестов интерфейса
- **Факт:** CI — Python + tsc/build. Нет Playwright для камеры, мобильной
  шторки, развёрток, strict-ошибки, переключения проектов.
- **Риск:** регрессии UI ловятся только вручную; мобильный dead-end
  (уже исправлен) мог остаться.
- **Решение:** smoke Playwright на ПК 1440×900 и телефоне 390×844;
  скриншоты wall view / modal / mobile menu.

#### P1-8. Настенные предметы проверены не полностью
- **Факт:** `scene.py` проверяет `wallitem` против мебели/декора/проёма,
  но не проверяет выход за длину стены, тело стены и `wallitem × wallitem`.
- **Риск:** розетка/полка может висеть вне стены или пересекать другую.
- **Решение:** добавить проверки длины/толщины/пар и тесты.

### P2 — техдолг и удобство

- **P2-1. Нет undo для нормализации.** `LayoutPanel` применяет перемещения
  мебели/декора без `pushHistory`; «Отменить» не вернёт.
- **P2-2. Гость плодит записи.** Каждый `/api/auth/demo` создаёт пользователя
  и проект; нет лимита/очистки.
- **P2-3. Нет rate limit** на login/demo/solve/PUT.
- **P2-4. Бандл 1.6 MB** (`index-*.js`, dist 2.5 MB); нет code splitting;
  Babylon грузится целиком.
- **P2-5. Монолитные файлы:** `state/project.ts` 140 KB,
  `ModuleWorkbench.vue` 68 KB, `scene.py`/`layout.py` дублируют геометрию.
- **P2-6. Документация дрейфует:** счётчики тестов (19/20/21),
  `docs/23` не отражает последние изменения; нет единого changelog статусов.
- **P2-7. `solveInitial` на телефоне** в тесте показывал `расчёт…` дольше
  6 с; нужен реальный замер/FPS.
- **P2-8. Точность створок:** фасадные двери считаются по шаблону
  `left/right` из `params`, а не по фактическим `hinge` из solver;
  кастомные `fronts` и углы 80–110° пока приблизительны. Ящики — 450 мм.

## 4. Точность расчётов: контрольные факты

| Проверка | Факт |
|---|---|
| База 600×720×560 | BOM: боковины 560×720, крыша/дно 568×560, полка 565×540 |
| Цоколь | 568×100; при `H=100` solver уменьшает до 68 и пишет предупреждение |
| Столешница | 600×38, верх 858 мм при plinth 100 |
| Задняя стенка | 600×720 (при `W=600/H=720`), документация обещает 598×718 |
| Дверь 600 | 596×716 (зазоры 2/3), ок |
| Раскрой/кромка | golden/geometry/features зелёные |
| Демо | `demo-apartment` 0, `demo` 0 |

Вывод: **арифметика деталей стабильна**, но семантика `H` и задней стенки
требует фиксации стандарта.

## 5. Стандарты

- **ГОСТ/внутренние правила:** зазоры 2–3 мм, двери ≤600, ящики ≤900,
  кромка только на видимых торцах — в основном соблюдены.
- **Нулевой зазор фасадов** технически разрешён (`gapBetween=0`) и покрыт
  тестом, но противоречит `docs/10` (2–3 мм) и даёт только warning.
  Нужно либо запретить, либо явно помечать как «осознанное переопределение».
- **Back panel** — см. P1-2, противоречие документации и кода.
- **Цоколь/столешница** — solver корректно ограничивает, но UI не показывает
  полную высоту.
- **Проверка стандартов** должна попадать в CI (есть), но нет теста
  «документация = движок» (back panel бы поймал).

## 6. UX/интуитивность

Хорошо:
- единое меню, иконки, проекты;
- мобильная компактная шторка;
- инспектор объекта, слайд «Объект/Деталь»;
- развёртки стен без WebGL;
- быстрые ошибки с переходом к модулю.

Проблемы:
- **развёртки без зума** — главный барьер для длинных стен;
- сырые коды в панели расстановки;
- ошибки декора не кликабельны;
- `H` без пометки «корпус/полная»;
- нет явного индикатора «только комната / загружено всё»;
- 2D-режим на мобильном теперь имеет свою шапку (исправлено в этом аудите),
  но длинная стена всё равно мелкая;
- нет печати/PDF развёрток.

## 7. Безопасность и эксплуатация

- `COOKIE_SECURE=0` на HTTPS — **исправить**.
- `APP_SECRET` fallback в compose — **убрать fallback для production**.
- `/api/auth/demo` создаёт гостя/проект на каждый клик — лимит/очистка.
- Login/demo/solve/PUT без rate limit — добавить.
- `.env` в `.gitignore` — ок.
- CORS ограничен localhost — ок для одного origin; для отдельного фронта
  добавить домен.
- Docker healthchecks/restart есть; публичный health 200.

## 8. План исправлений

1. **P0-1** — быстрый `normalize_scene` (локальные препятствия, цель <300 мс).
2. **P0-2** — preflight-проверка перед сохранением UI/strict.

## 9. Вердикт

Система **готова к ограниченной эксплуатации** (демо, один цех, ручная
проверка), но **не готова к полностью автоматической ИИ-генерации без
человека** из-за P0-1/P0-2. Ядро расчётов и валидация — сильные; основные
риски сейчас в производительности нормализации, обязательности проверки
в UI и нескольких расхождениях «документация ↔ движок».
