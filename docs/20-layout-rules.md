# 20 — Расстановка мебели: правила, проверка и автоплотнение

> Статус: **рабочий контракт** для UI, API и будущего ИИ-агента.
> Код: `tools/furniture_core/layout.py` + `apps/web/src/state/project.ts`
> (`wallBodyHit`, `wallFaces`, `snapPlacement`).
> API: `GET /api/projects/{id}/layout`,
> `POST /api/projects/{id}/layout/normalize`.

Эргономика и безопасность размеров — `docs/29-furniture-standards.md`
(ГОСТ 13025.1/.2/.3, ГОСТ 16371, EN 1116, EN 14749); коды `std-*`.

Этот документ — не советы по дизайну, а **исполняемые правила**. Если правило
нарушено, проект не считается готовым: валидатор расстановки обязан выдать
ошибку, а агент — исправить или спросить человека.

---

## 1. Координаты и модель комнаты

| Что | Правило |
|---|---|
| План | X — вдоль, Y — глубина, миллиметры |
| Высота | Z, миллиметры; 0 — пол |
| Модуль | `x,y` — левый-передний угол в плане; `rot` — градусы |
| Фасад | локальная сторона `y = 0`; задняя стенка — `y = D` |
| Контур `room.outline` | **внутренние** грани наружных стен |
| Наружная стена | уходит **наружу** от контура на `room.wallT` |
| Перегородка | осевая линия `a→b`; тело уходит в сторону `-n` на `partition.wallT` |
| Внутренние грани перегородки | две: на линии (`offset 0`, нормаль `n`) и на `-t` (нормаль `-n`) |
| Проём | `wall` (индекс `roomWalls`), `x` вдоль стены от её начала, `w`, `z0..z1` |

Следствие: **нельзя** ставить корпус на осевую линию перегородки. Для стены
толщиной 140 мм между «линией» и «гранью» есть 140 мм, и корпус либо заходит в
стену, либо оказывается в соседней комнате.

### 1.1. Углы и поворот

`rot = 0` — задняя стенка смотрит в `+Y`, фасад в `-Y`.
`rot = 90` — задняя в `-X`, фасад в `+X` (и т.д. по часовой).
Вектор задней стенки: `back = (-sin rot, cos rot)`.

Чтобы поставить шкаф **спиной к стене с нормалью `n`** (нормаль смотрит в
комнату), нужно `dot(back, -n) ≈ 1`. Для стены `+Y` это `rot = 0`;
для стены `-Y` — `rot = 180`; для стены `+X` — `rot = 270`; для `-X` — `rot = 90`.

## 2. Железные инварианты (ошибки)

1. **Не в стене.** Корпус не пересекает тело стены `[-t, 0]` вдоль нормали.
2. **Не за контуром.** Все углы корпуса — внутри `outline` (допуск 1,5 мм на
   примыкание к грани).
3. **Не перекрывает проём.** Корпус не попадает в полосу двери/окна:
   * дверь — свободно **не менее 420 мм и не меньше ширины полотна** с обеих сторон по нормали;
   * окно — **80 мм** от стены; по Z корпус не должен пересекать `z0..z1`.
4. **Не пересекает другой корпус** по плану и по высоте одновременно.
5. **Не стоит фасадом в стену.** Если фасад упирается в грань, модуль
   разворачивается на 180°.
6. **Не «висит» в толще стены.** Зазор между задней стенкой и внутренней
   гранью — **0 мм** (примыкание), а не 50/100 мм.
7. **Цоколь не выше корпуса и не под полом.** `0 <= plinthH < H`.
   Фактическая высота напольного модуля: `z + plinthH + H + worktopT`;
   она не может быть ниже 0 или выше `room.h`.
8. **Декор — такое же твёрдое тело.** Растения, ТВ, сантехника, комоды,
   ковры (кроме ковра как покрытия пола) не пересекают стены, проёмы,
   мебель и друг друга.
9. **Дверь фасада не бьёт по чужому телу.** При открывании створка не
   задевает стену, проём, соседний модуль, декор или другую створку.
   Проверяется зона открывания перед модулем.
10. **Непрерывный ряд без разрывов.** Кухня/гардероб/шкафы, стоящие на
    одной грани и одном уровне низа, — только вплотную (`gap = 0`).
    Разрыв > 2 мм — ошибка; зазор допустим только на проёме.

## 3. Обязательные правила ряда

1. **Корпуса в ряду — вплотную.** Зазор между корпусами **0 мм**.
   Декоративные зазоры 2–3 мм — это зазоры **фасадов** (`gapSide`,
   `gapBetween`), они уже внутри модуля. Нельзя добавлять их между корпусами.
2. **Один ряд = одна задняя грань + один уровень низа.**
   Напольные модули (z=0), навесные (z=1450) и высокие (z=0, H>1500) —
   разные ряды. Высокий пенал/холодильник может стоять в ряду напольных.
3. **Одинаковая глубина ряда** (если производитель не предусмотрел выступ).
   Холодильник/пенал может выступать вперёд — это осознанное исключение,
   его задняя стенка всё равно на грани.
4. **Столешница/цоколь/фартук** считаются по ряду, а не по каждому модулю.
5. **Нельзя закрывать дверь ради «ровного ряда».** Если ряд упирается в
   дверь — ряд разрывается, ставится заполнитель/стойка, или дверь
   переносится **решением человека**, а не автоматически.

## 4. Навесная мебель и эргономика

1. Верхние шкафы: низ **не ниже 1350–1500 мм** от пола, верх — по высоте
   комнаты/фартука.
2. Ручка навесной двери — **у нижней кромки** створки (`door_top` от низа),
   чтобы до неё дотягивался человек. Ручка у верхней кромки навесного шкафа —
   ошибка.
3. Ручка напольной двери — у **верхней** кромки створки.
4. Ручка ящика — по центру фасада ящика.
5. Глубина навесных — 300–350 мм; напольных — 550–600 мм; высоких — 600–650 мм.
6. Верхние шкафы не перекрывают окно: либо короче, либо выше/ниже проёма.

## 5. Петли, кромка, крепёж

1. Петля — **одна сторона** створки. Чашка на двери, ответные планки — только
   на той боковине, к которой петля. Второй стороны быть не должно.
2. Каждая физическая деталь (дверь, полка, боковина) имеет свой `op_part`:
   `"Фасад дверь · 1.2"`. Иначе карта присадки склеивает две одинаковые двери
   и показывает отверстия «слева и справа» на одном полотне.
3. Кромка — только на видимых торцах (`docs/02-edging.md`). Внутренние торцы
   в ряду (примыкание корпусов) — без кромки.
4. Для двух дверей в одной секции: левая — петля слева, правая — справа;
   ручки встречаются в центре. Для 4 дверей — пары `(L,R),(L,R)`.
5. Не ставить ручку на профиль/ push-to-open: `centers < 0` — ручек нет.

## 6. Алгоритм проверки (`validate_layout` + `validate_scene`)

`validate_layout` проверяет план/стены/ряды, `validate_scene` — объёмы,
декор, высоты и двери. API объединяет их и убирает дубли.

1. Построить 4 угла повёрнутого прямоугольника.
2. Проверить `inside outline` с допуском 1,5 мм.
3. Для каждой стены спроецировать углы в `(s, o)`:
   * если `s` вне `[0, L]` — стена не участвует;
   * если `o` пересекает `[-t, 0]` — ошибка `in-wall`;
   * для каждого проёма: если `s` пересекает `[x, x+w]`, `z` пересекает
     `z0..z1`, и `o` в зоне двери/окна — ошибка `opening`.
4. Для каждой внутренней грани: если `min(o) ≈ 0` и фасад смотрит в грань —
   предупреждение `front-to-wall`.
5. Пары модулей: пересечение по плану и Z — `overlap`; для одного ряда
   (грань + уровень низа + зона) — разрыв `> 2 мм` — **error**; для разных
   рядов — только предупреждение.
6. Объёмная проверка: реальная высота (`plinth + H + worktop`), цоколь
   `0 <= plinth < H`, пол/потолок.
7. Декор: контур, стены, проёмы, мебель, декор×декор. Ковёр не считается
   объёмом для мебели, но не может выходить за комнату/стену.
8. Двери фасадов: зона открывания перед модулем (ширина створки) против
   стен, проёмов, модулей, декора и других створок.
9. Результат: `{ok, errors, warnings, issues[]}`.

### 6.1. Планировочные проверки (в коде, не только в тексте)

Эти принципы раньше жили только в документе — теперь их проверяет
`validate_scene`, а значит и preflight, и strict-сохранение, и тесты:

| Код | Уровень | Что ловит |
|---|---|---|
| `socket-over-cutout` | error | розетка/выключатель над мойкой или варочной (на уровне столешницы) |
| `cabinet-window` | error | навесной шкаф перекрывает окно по ширине и высоте |
| `cabinet-window-gap` | warning | до окна меньше 80 мм — не хватит откоса |
| `sink-corner` | warning | мойка/варочная ближе 50 мм к боковой стене |
| `row-gap-wall` | warning | ряд не доходит до стены на 30…250 мм — нужен заполнитель (толщина перегородки не считается щелью) |

Уровни: `error` — проект нельзя отдавать; `warn` — можно, но агент обязан
объяснить/исправить.

## 7. Алгоритм автоплотнения (`normalize_layout`)

1. Для каждого модуля найти ближайшую подходящую внутреннюю грань:
   * наружная стена — только внутренняя грань;
   * перегородка — та грань, с чьей открытой стороны стоит модуль.
2. Если корпус пересекает тело стены — сдвинуть по нормали к ближайшей грани.
3. Если корпус в 0…260 мм от грани и его задняя стенка смотрит на грань —
   прижать вплотную.
4. Если фасад смотрит в грань — повернуть на 180° и снова прижать.
5. Для каждого ряда (грань + уровень низа) отсортировать по `s` и сдвинуть
   модули влево, закрывая зазоры `0 < gap ≤ 200`. Зазор, попавший на дверь,
   **не закрывается**.
6. `normalize_scene` разводит конфликтующий декор в ближайшую свободную
   точку; мебель/двери автоматически не двигаются.
7. Пересчитать `validate_layout` + `validate_scene`; `commit` только при
   `errors = 0`.

Автоплотнение **не** переносит двери и не меняет комнату. Если после него
остались ошибки `opening` — это решение человека: разорвать ряд, перенести
дверь или убрать модуль.

## 8. API для ИИ-агента

```http
python3 tools/validate_project.py projects/<id>/project.json

GET  /api/projects/{id}/layout
→ {"ok": true, "errors": 0, "warnings": 2, "issues": [...]}

POST /api/projects/{id}/layout/normalize
     {"commit": true, "closeGaps": true}
→ {"ok": true, "changes": [...], "issues": [...], "committed": true}

PUT  /api/projects/{id}?strict=1
→ 422 {"detail": {"message": "...", "errors": N, "issues": [...]}}
   если есть ошибки; чистый проект сохраняется.

POST /api/projects/{id}/actions
     {"actions": [...], "commit": true, "strict": true}
→ 422 с issues, если изменения ломают расстановку.
```

`GET /api/ai/guide` содержит те же правила в машинно-читаемом виде.

### 8.1. Пайплайн создания проекта агентом

1. `GET /api/projects/{id}` — комната, контур, перегородки, проёмы.
2. Определить **зону/комнату** для каждого модуля (спальня, кухня-гостиная,
   гардеробная, ванная). Не ставить кухню на стену с дверью в ванную.
3. Для каждой стены построить свободные интервалы `L` за вычетом проёмов
   (дверь + 420 мм с каждой стороны по нормали, окно + 80 мм).
4. Разместить ряд: ширина модулей + 0 зазор, задняя стенка на внутренней
   грани, фасад в комнату.
5. Высокие модули (пенал, холодильник) — в конец ряда, не под окно.
6. Навесные — над напольными, низ 1350–1500 мм, ручки снизу.
7. `POST /layout/normalize` с `commit=false` — предпросмотр.
8. `POST /layout/normalize` с `commit=true` — применить (нормализация не
   двигает декор и не чинит двери — их надо поправить вручную).
9. `GET /layout` — должно быть `errors = 0`. Сохранять только через
   `PUT ?strict=1` или `actions {commit:true, strict:true}`.
10. `POST /api/solve` для каждого модуля — деталировка/присадка.
11. Отдать человеку на подтверждение (необратимые действия — только с ним).

### 8.2. Что агент НЕ делает сам

- Не двигает двери/окна и не удаляет их.
- Не меняет размеры комнаты.
- Не «подгоняет» размеры модулей под мебель без задания клиента.
- Не ставит мебель в проём «потому что так ровнее».
- Не выдаёт проект с `errors > 0`.

## 9. Частые ошибки и как их ловить

| Симптом | Причина | Правило |
|---|---|---|
| Шкаф «в стене», спина в другой комнате | поставили на осевую линию перегородки | прижать к внутренней грани, `in-wall` |
| Кухня перед дверью | ряд считали без проёмов | свободные интервалы, `opening` |
| 50 мм между тумбами | шаг расстановки/копирование +50 | `gap`, автоплотнение |
| Ручки сверху навесных | одна формула для всех | `mount=wall` → ручка снизу |
| Петли с двух сторон одной двери | операции склеены по имени детали | `op_part` на каждую физическую деталь |
| Тултип присадки «улетел» | `position:fixed` внутри transform-модалки | `Teleport to body` |

## 10. Чек-лист перед выдачей

- [ ] `GET /layout` → `errors = 0`.
- [ ] Ни один корпус не в стене и не за контуром.
- [ ] Ни один проём не перекрыт.
- [ ] Все ряды без зазоров между корпусами.
- [ ] Цоколь: `0 <= plinthH < H`; фактический верх не выше потолка.
- [ ] Декор не в стене/проёме и не пересекает мебель.
- [ ] Двери фасадов не задевают стены, проёмы, мебель и декор.
- [ ] Задняя стенка на внутренней грани, фасад в комнату.
- [ ] Навесные: ручки снизу, низ 1350–1500 мм.
- [ ] Петли только на стороне петли; у каждой двери своя карта присадки.
- [ ] Кромка только на видимых торцах.
