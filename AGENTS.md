# AGENTS.md — как ИИ-агентам работать в проекте Furniture

Этот файл — **обязателен к прочтению** агентом перед любой задачей в этом проекте.
Он задаёт правила, конвенции и куда что класть.

## 1. Что это за проект

Дом для всего мебельного: правила, движок, 3D, видео, превью, карточки.
Работа ведётся ИИ-агентами (opencode) под контролем человека.

## 2. Железные правила

1. **Правила — в `docs/`, данные — в `specs/`, код — в `tools/`, изделия — в `projects/`.**
   Не сваливать всё в одну папку.
2. **Не менять `tools/*.py` без прогона проверки** (`python3 tools/kitchen.py ...` и валидатор
   не должен давать ошибок).
3. **Длинные детали** (> формата листа) — сегментировать.
4. **Кромка — только на видимые торцы** (см. `docs/02-edging.md`).
5. **Перегородки — только по конструкции или явному запросу.** Две двери сами по себе
   не требуют средней стойки: створки вешаются на крайние боковины. Каждая секция —
   отдельный модуль со своими стенками и **своей крышкой**.
6. **Каждый элемент — отдельный объект** в Blender (ничего не склеивать по материалу).
7. **Не выдумывать размеры.** Вход — только из размеров клиента или спецификации.
8. Всё необратимое (заказ раскроя, деньги) — только с подтверждением человека.

## 3. Три слоя знаний (не путать)

| Слой | Где | Пример |
|---|---|---|
| Универсальные правила | `docs/` | «вкладная деталь = −2t» |
| Цеховые (per раскройщик) | `specs/shop-*.yaml` | формат листа, пропил |
| Брендовые (per фурнитура) | `specs/hardware-catalog.md` | присадка Blum/Hettich |

Правило = то, что всегда верно. Настройка = то, что зависит от цеха/клиента.
Всё остальное — **явный вопрос**, а не догадка.

## 4. Куда класть результат

| Что | Куда |
|---|---|
| Новое изделие/заказ | `projects/<имя>/` |
| Деталировка, раскрой, DXF | `projects/<имя>/` |
| 3D-рендеры | `projects/<имя>/renders/` |
| Видео | `projects/<имя>/video/` |
| Превью/миниатюры | `projects/<имя>/previews/` |
| Карточки товаров | `projects/<имя>/cards/` |
| Материалы/текстуры/модели | `assets/{materials,textures,hardware}/` |
| Новые правила/специфика | `docs/` |
| Новые данные цеха/бренда | `specs/` |

## 5. Рабочий цикл

```
1. Прочитать docs/01-design-rules.md + docs/10-standards.md
2. Взять/уточнить вход (размеры клиента)
3. Прогнать tools/kitchen.py  → деталировка + раскрой + DXF + scene3d.json
4. Проверить валидатор (ошибок быть не должно)
5. 3D: tools/blender_build.py → .blend + рендеры (+ тур)
6. Контент: видео / превью / карточки → projects/<имя>/
7. Записать решение/стандарт в docs/ или specs/
```

## 6. Соглашения

- **Единицы:** миллиметры. В Blender — метры (÷1000).
- **Координаты 3D:** X — длина (0…L), Y — глубина (0 = фасад), Z — вверх (0 = пол).
- **Имена объектов Blender:** `Деталь·<номер секции>` (напр. `Крыша·3`).
- **Торец:** видимый помечается `ПЕРЕД`.
- **Язык документации:** русский; код и имена папок — английские.
- **Коммиты:** только по явной просьбе человека.

## 7. Что нельзя

- Склеивать разные детали в один объект/меш.
- Ставить кромку на скрытые торцы.
- Оставлять дверь без стойки для петли.
- Общие (совмещённые) стенки между секциями — секции независимы.
- Выдавать заказчику результат с ошибками валидатора.

## 8. Проверка перед выдачей

- [ ] Валидатор: ошибок нет.
- [ ] `python3 tests/golden.py` — эталоны совпали (или `--update` с причиной в `docs/10`).
- [ ] `python3 tests/geometry.py` — пересечений деталей нет.
- [ ] `python3 tests/features.py` — фасады/задник/царги/навесные/вырезы/толщина.
- [ ] Кромка только на видимом.
- [ ] У каждой двери есть стойка; у каждой секции своя крышка/стенки.
- [ ] Раскрой: все детали влезли, КПД разумный.
- [ ] Файлы разложены по структуре выше.
